# Публикация статьи на сайт zhivoy-ai.ru

Применяй этот скилл, когда нужно опубликовать новую статью на
zhivoy-ai.ru (сайт на GitHub Pages, обычный HTML/JS, без CMS).
Сначала прочитай `CLAUDE.md` в корне репозитория: там устройство сайта и скрипты.

Помогай публиковать статью строго по этому чек-листу, по порядку,
ничего не пропуская:

1. Создать папку `articles/имя-статьи/` (имя латиницей, цифры и дефисы, коротко и понятно по смыслу статьи). Если такая папка уже есть, остановиться (см. «Если статья уже есть»).
2. Создать в этой папке файл `data.json` ровно с 5 полями:
   - `title` — заголовок статьи;
   - `date` — дата в виде ГГГГ-ММ-ДД;
   - `tag` — рубрика, только одна из кнопок-фильтров главной: `музыка`, `промпты`, `тексты`, `реальные-истории`;
   - `excerpt` — короткое описание для главной, поиска и соцсетей (до 155 знаков);
   - `content` — HTML статьи вместе с картинками и видео.
3. Залить все медиафайлы (картинки/видео) статьи в ту же папку `articles/имя-статьи/`. Обложку назвать `cover.jpg` (или `.png`/`.webp`): её скрипт возьмёт для превью и соцсетей. Картинки тяжелее 300 КБ сначала сжать.
4. В `content` прописывать пути к медиа только как `src="имя-файла"`, без папок: файлы лежат рядом. У каждой картинки содержательный `alt`.
5–6. Запустить `node scripts/new-article.mjs имя-статьи`. Скрипт:
   - проверяет `data.json`, рубрику и что все файлы из `content` на месте;
   - создаёт `index.html` по тому же шаблону, что и приложение «Контроль» (шаблон берётся из `shtab-d14558/app.js`, отдельной копии нет). Без этого файла ссылка на статью отдаёт 404;
   - добавляет статью в `articles/manifest.json` (оглавление главной) и в `sitemap.xml` (для поисковиков).
   Если скрипт выдал ✗ — исправить и запустить ещё раз. Руками `index.html` не копировать.
7. Запустить `node scripts/check-site.mjs` — ошибок (✗) быть не должно. После выкладки открыть статью на zhivoy-ai.ru: открывается ли страница, подтягиваются ли картинки (не вылезают ли за карточку), не битые ли ссылки.

## Даты публикации при пакетной загрузке нескольких статей

Когда публикуется сразу пачка статей (например, 12-15 штук за один заход) — НЕ ставить всем одну и ту же дату (дату, когда их фактически загрузили). Вместо этого:

1. Найти дату последней уже опубликованной на сайте статьи (самая свежая запись в `manifest.json`).
2. Посчитать разницу в днях между этой датой и сегодняшним днём.
3. Равномерно распределить новые статьи по этим дням — по одной или несколько статей на каждый день, от следующего дня после последней публикации до сегодня включительно. Например: последняя статья на сайте была от 20 числа, публикуем 24 числа — значит есть 4 дня (21, 22, 23, 24), и 15 статей раскидываются по ним равномерно, а не все закидываются 24-м числом.
4. Если статей меньше, чем дней — можно пропускать дни или ставить по одной в день, начиная с более ранних дат, лишь бы не скапливать всё в один день.
5. Порядок распределения (какая статья на какую дату) — по смыслу: более старые по факту публикации в ВК/Telegram темы ставить более ранними датами внутри этого диапазона.

Скрипт `new-article.mjs` принимает сразу несколько slug: `node scripts/new-article.mjs slug1 slug2 slug3`.

Это нужно, чтобы лента статей на сайте не выглядела так, будто все материалы появились в один день, а данные `sitemap.xml`/SEO были более естественными по времени.

## Технический контекст сайта (не менять без явной просьбы)

- Репозиторий `zhivoy-blog/zhivoy-blog.github.io`, домен через CNAME.
- Каждая статья — отдельная страница `articles/имя-статьи/index.html` со своими title/description/og-тегами. `data.json` через fetch загружается этой страницей и подставляется в разметку.
- Старый `article-template.html?article=slug` для новых статей не используется, но файл **не удалять**: по нему работают старые ссылки.
- Стили — в `article-style.css`, логика — в `article-script.js`; в общих стилях сайта есть правило, что картинка внутри статьи никогда не должна выходить за границы карточки — не убирать это правило.
- Приложение «Живой ИИ: Контроль» при переносе статьи не добавляет её в `sitemap.xml`. После его публикаций `check-site.mjs` это покажет — дописать через `new-article.mjs`.

## Если статья уже есть

Если статья с таким slug уже существует на сайте (например, её уже перенесло приложение «Живой ИИ: Контроль») — не перезаписывать и не создавать дубликат, а прямо сказать об этом в отчёте: какие статьи уже были на месте и остались нетронутыми. `new-article.mjs` без `--force` существующую страницу не перезаписывает.

## Перед отчётом о готовности

Пройдись по всем 7 пунктам чек-листа вслух и подтверди явно, что каждый выполнен, и приложи итог `check-site.mjs`. Если что-то не сделано — не говори «готово», а укажи, какой шаг остался.

При пакетной публикации — явно подтвердить в отчёте, что даты распределены по дням, а не поставлены одной датой, и показать итоговое распределение (какая статья на какое число).
